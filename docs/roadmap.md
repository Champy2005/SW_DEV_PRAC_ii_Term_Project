# Delivery priorities

The detailed [delivery plan](plan.md) and [ticket board](tickets.md) are the authoritative sequence and status source. Read the board to see the current batch, dependencies, acceptance criteria, and short human review steps.

The committed starter already implements the main member/admin flows, rule-boundary fixtures, and saved shortlist. Existing code and historical passing tests are not a fresh acceptance result. Record new evidence in [verification](verification.md); mark a ticket accepted only after the user's review.

Prioritize mandatory functions, readable implementation, and verified role/business rules before optional polish. Then complete the UI flow, persistent deployment, regression checks, presentation, and submission gates. Do not add unrelated features or duplicate test frameworks.

The [course delivery checklist](course-delivery.md) records the **18 November 2026, 23:00 Bangkok** hand-in deadline, booking dates, exact demo journey, and required artifacts/links. Deployment preparation and final hand-in are separate from actually publishing, booking, or submitting, which remain human-owned or separately authorized actions.
